Welcome to Gewu Insight

Gewu Insight is a local workspace for collecting papers, preserving their files and versions, and following journals, subjects, authors, and your own publications.

Guide revision · September 6, 2026 · Functional review

Why this workspace exists

Research rarely arrives as one clean collection. A paper may first appear in a feed, later acquire an arXiv version and a DOI, be downloaded under several filenames, reappear through an author's profile, and eventually become part of a project or your own publication record. Publisher pages, alerts, PDFs, folders, notes, and citation services each preserve only part of that history.

Gewu Insight is designed to keep those fragments connected. It treats discovery, identity, files, versions, organization, reading state, and provenance as parts of one continuing research process. The aim is not to accumulate the largest possible list. The aim is to preserve enough context that a useful paper remains understandable and usable months or years after it was first found.

Why the name 格物洞见

The name recalls the Chinese idea of 格物致知: approaching things closely enough to understand their underlying order. In this practical research setting, gewu—the investigation of things—means continuously examining the research object, its sources, authors, versions, files, relationships, and changing state.

Keep research objects visible, evidence traceable, and insight cumulative.让研究对象保持可见，让证据保持可追，让洞见能够积累。

Five design commitments

Local ownershipYour live database and managed research files remain in the local project. Online services contribute evidence; they do not own the workspace.
Visible evidencePDFs and attachments remain real files that Finder, Preview, and other applications can inspect.
Continuity over timeA preprint, later DOI, publication version, annotations, and personal contexts can accumulate around one persistent paper object.
Explicit state and provenanceCompleted, empty, partial, failed, downloaded, imported, and retried are different states. Sources and operational outcomes should remain visible.
Researcher controlAutomation assists discovery and maintenance, but classification, interpretation, organization, and scientific judgment remain yours.
Local-first does not mean offline-onlyThe durable workspace is local, while supported discovery, metadata, profile, and download features may require network access and remain subject to source, publisher, and institutional availability. Verify uncertain matches and versions; the app does not bypass access controls.

Gewu Insight separates its portable Python, SQLite, and web-interface core from the native desktop layer. Paper identity, database migrations, monitor state, resource relationships, and most interface logic are designed without making macOS the definition of the product.

Add and inspect a paper

  1. Open Library. Select an existing folder, or create one from the context menu.
  2. Add a paper. Drag a PDF into the folder, or open the target folder, Control-click blank space in its contents, choose Add Paper, and enter a DOI, arXiv identifier, supported URL, or title.
  3. Select the new item. Paper Details appears at the right. Gewu Insight attempts to identify the work. A local file is recorded only when you imported one or a supported download succeeded.
  4. Check DOI and arXiv. Enter a corrected DOI in its field and refresh it, or edit arXiv inline and press Return.
  5. Inspect the available evidence. If a local PDF exists, choose Open in Preview, or enter Paper Files and press Space for Quick Look. If no file exists yet, use Open Website or download a supported version when one is available.

The paper now has a cataloged paper record, a stable Gewu Key, and a Library placement. It may have no local file; that cataloged-only state is valid. A file resource exists only after a file is imported, downloaded, or attached.

Understand what may now exist

Verify the identity before enriching it

  1. Compare the title and authors with the PDF. A similar title is useful evidence but not sufficient proof.
  2. Check the DOI and arXiv fields. A work can have both. Correct an inaccurate identifier before refreshing more metadata or downloading another version.
  3. Read the source and journal information. Confirm that a publication record belongs to this work rather than a cited paper or a similarly named article.
  4. Keep uncertainty visible. It is safer to leave a field empty than to confirm a plausible but wrong identifier.

Complete the first Paper Files bundle

A cataloged-only paper may have no local file, and nothing is missing merely because Paper Files is empty. Continue with these steps after you import, download, or attach a file and the paper becomes file-backed.

  1. Select the paper to show Paper Files. Cards initially show File type and size. Click a card's size footer to show or hide Annotation and Source.
  2. Classify the available file. Use its small type, annotation, and source controls. Do not infer these facts from the filename alone.
  3. Add related material if you have it. Add a supplement, annotated copy, note, presentation, data file, code file, or other attachment. Import first, then classify the resource.
  4. Check the default file. Open in Preview and Library preview use the resolved default when applicable. Selecting Set as Default changes preference without renaming the resource.
  5. Reveal one file in Finder. Choose Show in Finder and confirm the real managed file exists where the database expects it.
Cataloged and organizedThe shared paper record and Library placement are durable even when no local file has been added.
File-backedAfter a file is added, its independent file properties and physical bytes can be inspected separately from paper identity and folder context.

Optional: verify shared identity

Copy the paper to a second Library folder, then select it there. The title, Gewu Key, Paper Files, and metadata should remain the same because the second folder contains another placement for the shared paper—not an unrelated duplicate. Delete only the extra placement when you are finished with the check.

Paper Details, Paper Files, and Finder should answer the applicable questions without contradicting one another.

Understand the System

See the System Architecture at a Glance

Gewu Insight is a local research system that coordinates structured state, visible files, and a personal workspace. It is not simply a web page placed in front of a folder.

How the parts cooperate

The desktop window presents a local interface served from the project on the current computer. In today's primary release, a macOS shell supplies Finder, Preview, Quick Look, Dock, and native drag-and-drop integration. The Python, SQLite, and web-interface core is designed to support other desktop shells without changing the meaning of the research data. Network sources contribute evidence and downloadable material, but the durable workspace stays local.

What each persistent layer answers

Browser is a separate web surface. Its native WebKit views load websites directly, not through the Python service. The local service stores bookmarks and history in SQLite; WebKit manages a separate persistent website profile. External pages do not receive the Library's local API bridge. Visiting a page, saving a bookmark, or downloading through Browser does not create a paper or assign a Gewu Key; import the paper explicitly.

LayerQuestions it answersWhat it does not decide alone
SQLiteWhat is this paper? Where is it referenced? Which resources belong to it? What happened in the last operation?It does not contain the bytes of your PDFs and attachments.
FilesystemWhich real files can the native file manager, PDF reader, or another application open?A filename or folder position alone does not define paper identity, version priority, or monitor membership.
Personal Research WorkspaceHow should the shared state be presented for discovery, reading, organization, and action?It is a projection of saved state, not a separate copy of the collection.
Persistent research workspace = structured SQLite state + visible research files, coordinated by the local application.

Why this separation matters

A paper can appear in a Monitor, the Library, a Space, and My Publications without becoming four unrelated papers. It can also acquire a DOI after first arriving as an arXiv preprint, or acquire a publication PDF while retaining earlier versions. The database preserves continuity across those changes; visible files preserve user ownership and inspectability.

TerminologyThis guide uses Personal Research Workspace for the on-screen projection and Visible Research Files for assets visible to the native filesystem. These are explanatory terms, not menu names. Together they form the visible workspace, but they serve different roles.

Understand the Persistent Paper Object

Gewu Insight treats a scholarly work as an object that persists through discovery, publication, file changes, and personal organization—not as a temporary search result or a single PDF.

One identity can accumulate evidence

The central record uses an internal paper identity. A DOI or arXiv identifier is important evidence attached to that identity, but neither is a safe universal primary key: an early preprint may have no DOI, an imported PDF may initially have no reliable identifier, and an incorrect identifier may later be corrected.

Do not collapse four different things

ObjectMeaningExample
Paper recordThe shared scholarly identity and normalized metadata.The work that later connects arXiv and a journal DOI.
Placement or relationWhy and where the paper appears in your workspace.A Library folder entry, a shortcut, a My Publications role, or an Author Monitor association.
Resource recordA described file or retrievable version belonging to the paper.Preprint v2, published version, supplementary material, peer review file, or data file.
Physical fileThe bytes stored at a real path on disk.A PDF under data/Library or an associated attachment.
Paper record ≠ workspace placement ≠ resource record ≠ physical file.

What happens when the same paper is found again

Journal, Subject, and Author Monitor can encounter the same work from different directions. Identity resolution is designed to reuse one shared paper record and add source or context relationships. Copying a paper to another Library folder likewise creates another placement rather than a second independent identity. Its metadata, Gewu Key, versions, and attachments remain shared.

When the available evidence is insufficient or contradictory, separate candidates can remain until their identifiers or metadata are corrected. A major DOI, title, author, or venue contradiction is quarantined as an identity conflict instead of overwriting the saved paper or forcing a merge. The shared-object model is the resolution target; it does not justify merging uncertain works merely because their titles look similar.

A network observation can be transient while acquisition is running. Once a result is cataloged as a shared paper record, it has a Gewu Key even if a particular Monitor view does not display that key. A Monitor result may still have no local Paper Files because no file has been downloaded or attached; adding it to Library creates a visible placement rather than inventing a new scholarly identity.

Gewu Insight also uses the same catalog and resource infrastructure for an imported standalone file whose scholarly identity is not yet known. In that case, the catalog record preserves the file and its relationships while later identification can enrich it.

Identity corrections should preserve continuity

Editing a DOI or arXiv identifier changes evidence on the existing paper. It should not silently make an unrelated second paper, rename every file, or discard your folder placements and read history. When evidence conflicts, inspect the title, authors, venue, and files before confirming the correction.

ImportantSimilar titles are not proof of identity, and matching filenames are not proof that two resources are the same. Use identifiers, metadata, file fingerprints, and provenance together.

Understand the System

Understand Why SQLite Is the Core

SQLite is the source of truth for Gewu Insight because it preserves the identity, relationships, resource registry, and operational memory that neither a filename nor an exported report can express.

Four families of structured state

The database does not store the PDF bytes themselves. It stores enough structured information to understand the files: which paper they belong to, what file type they represent, where they are, where they came from, whether they are annotated, and which one should be used by default.

Why a folder scan is not an equivalent database

Finder can show that paper.pdf exists. It cannot reliably say whether it is a published version or a preprint, whether it is annotated, where it came from, whether the same work is also in My Publications, or which file is the manual default. Those facts live in SQLite.

Transactions, relationships, and WAL

Database mechanismUser-facing purpose
TransactionsKeep a multi-step state change together so a partly applied edit is less likely to become the visible truth.
Foreign-key relationshipsConnect a resource or placement to the correct shared paper instead of relying on a coincidentally similar filename.
WAL (write-ahead logging)Lets foreground reading and background updates coexist more safely than repeated full-file rewrites.
Schema migrationAdds new structures and backfills required state during an upgrade rather than asking the user to rebuild the database.

WAL improves normal concurrency; it is not a substitute for a coherent backup. Close Gewu Insight before copying its live database, and back up the managed files with it.

Durable preferences and shipped defaults

Journal subscriptions are durable SQLite state as well. The database preserves which journals are enabled, their identifiers and source settings, and their display order. The journal catalog shipped with a newer app version is a set of defaults, not an instruction to overwrite your personal list.

On the first upgrade that introduces durable subscriptions, Gewu Insight seeds the database from the existing journal configuration and history. After that one-time seed, adding, disabling, restoring, or reordering a journal changes the database record. Replacing source code or rebuilding the app does not silently re-enable a journal you removed or discard journals you added.

Cross-layer changesSQLite transactions protect database state. A file move and its database update cannot be one native SQLite transaction, so the local service coordinates the steps and uses validation or compensating recovery when a filesystem operation fails.

Exports and provenance

JSON, HTML, Markdown, Word, LaTeX, and PDF outputs are derived artifacts. They can be regenerated, shared, or inspected, but editing them does not alter the source records. Raw source evidence may also be retained inside SQLite for provenance; this does not turn an external JSON export into a second source of truth.

Paper-level Monitor provenance

Normalized paper-source observations are the authority for how a canonical paper was encountered. Each observation identifies a source kind, provider name, and stable source key, and keeps first-seen and last-seen times. The same paper and effective source update one observation instead of increasing the provenance count indefinitely.

Journal Monitor also connects each observed paper to the relevant fetch run. The run supplies the journal, requested date window, status, and timing; the paper-level observation records that the reporting source saw this particular work. Subject and Author Monitor relationships can point to the same canonical paper, so three discovery routes add context without manufacturing three scholarly identities.

A bibliographic metadata refresh can add a newly proven source, but it cannot erase an earlier Journal, Subject, or Author observation. Display counts and the older raw-source list are compatibility projections of the normalized observations rather than an independent truth. When two paper identities are safely merged, their source observations move to the surviving canonical paper and duplicate observations converge.

Discovery is not storageA provenance relationship does not by itself create a Library placement or a local PDF. It records how the work entered view. Organization and file acquisition remain separate, explicit actions.

What the app does during an upgrade

On startup, the storage layer reads the database schema version, checks for required tables and fields, applies additive migrations in order, ensures required roots exist, and backfills stable keys or resource records where older data needs them. A normal migration preserves paper identities, folder placements, monitored-journal choices, fetch provenance, and file paths. This is why a project upgrade should preserve the existing database and files rather than replace them with an empty database.

Do not edit the live database manuallyA seemingly small manual change can violate a relationship that is not visible in one table. Use the app for normal work and make a closed, complete backup before any diagnostic intervention.

Understand Visible Research Files

Your PDFs and attachments remain real local files. Gewu Insight adds a resource model around them so several versions and related materials can belong to one paper without hiding them inside an opaque cloud library.

One paper, one file bundle

Managed and linked resources

Storage modeMeaningSafe expectation
ManagedThe active stored path is inside the Gewu Insight project data area.Move, classify, replace, or delete it through the app so paths and relationships change together.
LinkedThe active stored path remains outside the managed project data area.Availability depends on that external path, and the app should not silently reorganize it.

A resource can be managed while retaining a separate external source path as provenance. The existence of that source path does not by itself make the managed copy a linked resource, and the external original remains protected.

Folder Loader is a migration-oriented workflow. It imports a visible collection as a collection instead of asking you to classify every incoming file as an attachment before identity resolution. The original source path and the managed result remain conceptually distinct.

How the default file is resolved

An explicit manual default takes precedence while it still exists and is not classified as Invalid file. Otherwise, usable files are ranked as Corrected published version, Published version, Accepted manuscript, then Preprint. Secondary and unknown types remain visible peers but never become automatic defaults.

Supplementary material, Peer review file, Other, Unknown, and Invalid file do not become the automatic default. Any valid resource can still be selected manually; Invalid file is never eligible and remains visible only for audit and repair.

Published filesThe user-facing type is Published version. A later formal correction can be classified as Corrected published version; the correction notice itself remains a separate peer.

Fingerprints and annotations

When a PDF is imported, attached, or downloaded, its exact SHA-256, content-oriented fingerprint, annotation count, and annotated state are computed as the resource is registered. They do not depend on a later refresh. Exact SHA-256 answers “are these bytes identical?” Adding a highlight or note normally changes those bytes. The content fingerprint is designed to recognize the same underlying document while discounting annotation-only changes, allowing clean and annotated copies to be related without treating them as blindly interchangeable.

Gewu Insight counts user-created comments and markup—such as highlights, notes, drawings, stamps, and form edits—as annotations. Structural PDF elements such as publisher hyperlinks, internal navigation links, and ordinary page actions do not make a freshly downloaded publisher or arXiv PDF Annotated.

An exact duplicate can be reused instead of stored twice. A clean PDF and an annotated copy may have different exact hashes but the same content fingerprint; both can be retained when the annotation state is meaningful.

Why Finder and the UI do not look identical

The filesystem must expose practical paths and folders; the UI must expose the meaning of one paper bundle. A Library paper can therefore retain a compatibility primary file in the visible topic folder while related files live under a mirrored Associated Files path. Paper Files deliberately presents all resource records as flat peers instead of mirroring those physical directories.

ImportantDo not manually move or rename managed resources in Finder. The bytes may still exist, but the saved path and live workspace can disagree. Use an app-supported move, repair, or restore; do not assume a restart will rediscover an arbitrary manual move.

Understand the Personal Research Workspace

The five research views—Library, My Publications, Journal Monitor, Subject Monitor, and Author Monitor—share research objects. Browser is the sixth main tab, with its own website session. Moving between research views does not reset a paper's identity.

Views are relational projections

A Library folder answers “where do I organize this?” My Publications answers “how does this relate to my authorship?” Author Monitor answers “how does this relate to this researcher?” These are different relationships to the same possible work. The interface queries those relationships and projects the relevant controls, status, and files for the current task.

Library placements and shortcuts

A paper can have more than one Library placement. Copying it to another folder reuses the shared identity and resources. A shortcut tab is another entry point to a Library location, not another paper collection. A Space is an independent organizational root, but papers placed there can still reuse the same identity model.

Discovery does not require immediate file management

A Monitor result may remain a discovery relationship with metadata and status but no local Paper Files. A cataloged work already has a Gewu Key, which Author Monitor also shows. Downloading or attaching a file creates a resource relationship; adding the paper to Library creates a managed placement. Neither action should manufacture a second work merely because the user entered from another tab.

Why the same action can have different scope

Removing an author from Author Monitor removes that monitored-author relationship. Removing a shortcut removes an entry point. Moving a Library placement changes organization. Deleting a managed resource changes the paper's file bundle. The selected view supplies scope, while SQLite preserves what remains shared.

A useful mental modelThe UI shows a personal map of a shared object graph. It is “visible” because you can navigate and act on it, but SQLite—not pixels on the screen—preserves the graph.

Move from Discovery to Durable Memory

Gewu Insight connects monitoring, identity resolution, version handling, and personal organization into one repeatable research loop.

A paper can change without losing its history

  1. Acquire an early work. Subject Monitor finds an arXiv preprint. Its source and discovery context are stored.
  2. Identify the work. The title, authors, and arXiv identifier connect it to one shared paper identity.
  3. Resolve its first resource. A preprint PDF becomes the automatic default because no higher-priority file is available.
  4. Remember your context. You add it to a Library folder, read it, and attach notes or data.
  5. Acquire new evidence later. Journal Monitor or a metadata refresh finds the published DOI and a published file.
  6. Resolve without erasing. The published file becomes the automatic default unless a manual choice is sticky; the preprint and its provenance remain peer records.

Operational state is part of scientific memory

A result count alone is ambiguous. The app distinguishes work that was never attempted from work that completed with no results, partially completed, failed, or entered a cooldown before retry. It also remembers imports, downloads, metadata refreshes, source tasks, and read state so the next action can be informed rather than blindly repeated.

StateMeaningReason to preserve it
Empty and completeThe requested source or date was checked and returned no matching records.Prevents “zero” from being mistaken for “not run.”
PartialSome sources completed while another did not.Allows a targeted retry instead of discarding useful completed work.
FailedAn operation produced a specific error.Makes the failure visible and avoids pretending the result is authoritative.
Cooldown or retry scheduledA remote service asked the app to wait or a transient error needs backoff.Reduces repeated traffic and protects normal foreground use.

Background work should not seize the foreground

Fetches, metadata refreshes, and imports report progress in reserved status areas and save their state. You should still be able to browse already stored material. Where callers share an online service, service-specific pacing, locks, cooldowns, and retry policies coordinate their requests. These controls reduce unnecessary traffic; they cannot guarantee that a publisher will never rate-limit or block a network address.

The loop is user-directedGewu Insight preserves the consequences of what you monitor, save, read, ignore, classify, and publish. It does not silently replace your research judgment with an invisible global keyword filter.

A safe local research workspace changes only the object and relationship you intended while preserving shared identity, resources, provenance, and recoverable state.

Eight invariants behind normal operations

One shared identityThe same scholarly work should not fragment merely because several sources or folders found it.

Recovery is part of the design

Recycle keeps ordinary removals recoverable. Import batches and operation status provide evidence about what ran. Resource paths, hashes, and provenance help diagnose missing or duplicate files. Duplicate protection

Gewu Insight computes exact SHA-256 and PDF content fingerprints as each new resource is registered. An exact duplicate is reused instead of stored twice. A clean PDF and a genuinely annotated copy can share a content fingerprint while retaining different exact hashes, annotation counts, and labels.

Validation before replacement

A response is not accepted merely because it begins with %PDF-. Structural PDF validation rejects empty files, HTML responses, truncated downloads, missing valid endings, and content that cannot be parsed as a PDF. A download is written to a temporary file and replaces the destination only after validation succeeds. If the request or stream fails, an existing valid file remains untouched and a partial file is not registered as a resource.

Classification follows the file that actually arrived

A publisher download is classified from the file and source actually returned. A corrected published version outranks a published version automatically; a publisher reference, First Release, or accepted preview remains an accepted manuscript. A correction notice remains a separate peer and never becomes automatic merely because it came from a publisher.

A PDF URL stored in bibliographic metadata is only a retrieval lead. It does not create a Paper Files row until a download actually succeeds, the returned bytes pass validation, and a local resource is registered.

If a download is skipped because the local bytes already exist, that skipped operation does not relabel the existing file from metadata or a newly discovered URL. Correct the file type explicitly if the saved classification itself is wrong.

    • Full refresh — more network work and a longer run.
  4. Choose Import. Follow progress in the live log. Use Stop Import if necessary.
  5. Review the result. Open previous logs or the result guide when items need attention.

What Folder Loader preserves

  • The source folder’s relative hierarchy.
  • Existing managed targets and files on repeated imports.
  • An existing primary PDF rather than overwriting it.
  • A verified exported Paper Files relationship when a Gewu Insight manifest is present.

Folder Loader copies into Gewu Insight’s managed storage. It does not move, rename, or delete the external source files and folders you selected.

Delete an import batch

Delete Import is a rollback for the selected Loader batch, not a way to forget a log. Stop an active import first. The command removes database records created by that batch, eligible empty folders, its Loader reports, and managed local copies associated with the batch; eligible paths are sent to the macOS Trash. It never deletes the original external source directory.

ImportantReview the selected batch and make a backup before using Delete Import, especially if you have already reorganized or reused imported items.

Back Up or Move to Another Mac

A reliable transfer preserves both the SQLite database and the managed file roots. The app bundle alone is not your library.

Create a full backup

  1. Quit Gewu Insight with ⌘Q. Wait until background refresh or download work has stopped. Closing a window is not the same as quitting; also stop any separately launched local UI or CLI process before copying its database.
  2. Copy the complete project directory. This is the safest recovery unit because it keeps data, reports, config, the app source, and managed paths together.
  3. Preserve directory names and permissions. Do not separate SQLite from the managed file roots it describes.
  4. Store the backup separately. Use a second disk or a versioned backup location.

Back Up and Upgrade

  1. Quit the current version and make a full backup. Preserve SQLite and every managed file root together.
  2. Install or build the newer application. A normal software upgrade does not overwrite the existing data directory.
  3. Start the new version once. Required database schema changes run automatically against the existing SQLite database.
  4. Verify before deleting the backup. Open the default PDF, another Paper Files version, an attachment, and a My Publications entry.
NoteSchema migration updates database structure; it is not a reason to rebuild the database or re-import the Library. Keep the pre-upgrade backup until the new version has been checked.

Move to another Mac

  1. Install or update Gewu Insight on the destination Mac.
  2. Keep the destination app closed.
  3. Restore the matching database and managed file roots together. Do not mix a new database with an unrelated old Associated Files tree.
  4. Start the app and test representative works. Open a paper, an older version, and an attachment; verify My Publications and one monitor.

Transfer only part of a Library

Use Make Copy Desktop on the source Mac, move the complete exported folder, then use Folder Loader on the destination Mac. Keep its verified manifest intact.

Browser and credential backup boundaries

The project database includes Browser bookmarks, folders, history, and saved sidebar preferences. A bookmark HTML export transfers only bookmarks, not history or research papers. Open webpage tabs and unsubmitted forms are memory-only and are not restored after quitting.

WebKit website cookies, sign-ins, and cache belong to a macOS-managed Browser profile outside this project. Copying the project or a bookmark export is not a supported transfer of that profile; expect to sign in again on another Mac. Apple Passwords and its passkeys remain under macOS/iCloud management and are never part of a Gewu export. Optional metadata API keys saved in SQLite do travel with the database: keep full backups private.

ImportantNever migrate by copying only paper_monitor.sqlite or only the visible Library folder. Either choice leaves half of the managed state behind.

Refresh a date

  1. Select a day in the calendar. Small numbers below a day show stored result counts.
  2. Choose Refresh. The app requests all configured journal sources for that date.

Manage monitored journals

Open Journal Settings to add or manage a journal by name, ISSN, or known publication history. When an ISSN is missing, the app can look up a matching journal record before saving it. Review the match rather than relying on a similar title alone.

Drag journals vertically in Journal Filter or Journal Settings to set their order. The saved order controls the filter list and the journal groups in the report. Removing a journal disables the subscription without erasing its previously collected papers or its saved history.

Your enabled list, disabled history, ISSNs, source identifier, section policy, logo source, and display order are saved in SQLite. Product updates can add better built-in source definitions, but those defaults do not replace this personal state. Adding a previously removed journal restores it at the end of the active order.

Understand counts and filters

The number beside each journal is the total stored count for that journal on the selected day. It is deliberately independent of Field Filter. The field checkboxes narrow the paper cards you can see; they do not rewrite the journal totals. A journal can therefore show a nonzero count while the current field selection hides every one of its papers.

Calendar counts summarize stored day results. A zero count is meaningful only after the relevant source completed successfully. Read the source status before interpreting zero as “the journal published nothing.”

Daily scheduled updates

Journal Monitor is designed to keep a daily cached record through its scheduled update workflow. A scheduled run and a manual refresh use the same stored day results, so opening a date does not require downloading it again. Use a manual refresh when a scheduled source was missed, partial, or needs verification.

The scheduler belongs to the running local UI service; it does not wake a sleeping Mac or run while that service is stopped. See When automatic updates run for the current timing and restart boundaries.

Journal logos and mathematical text

Configured journal logos are downloaded into a local cache and reused from disk. The first successful request may require network access; changing dates and later launches should not repeatedly download the same logo. The cache is presentation data and can be rebuilt without changing subscriptions or papers.

Supported inline LaTeX in titles and abstracts is typeset after the math renderer becomes ready. On a cold launch, raw source may be visible briefly, then the current day is rendered again automatically; changing to another date and back should not be necessary. Title normalization also preserves recognized proper names and source capitalization such as Su–Schrieffer–Heeger and Monte Carlo while still cleaning all-uppercase metadata and formula spacing.

How discovery provenance is preserved

Each stored Journal result is related to the canonical paper, the fetch run, and the source that reported it. The run preserves the journal, requested date window, status, and timing. Seeing the same paper from Crossref and OpenAlex records both source observations against the same paper identity; seeing it again within one run does not create a duplicate relationship. Later runs remain separately traceable.

The same canonical paper can also acquire Subject Monitor and Author Monitor relationships. These discovery paths explain why the work is visible; they do not automatically add a Library placement or create a local Paper Files resource.

Filter and inspect

Use Journal Filter, Preprint Filter, and Field Filter. Journal and field choices combine to determine the visible cards, while the journal counts continue to describe the full selected day. Enable Figures to show a representative image when available. Selecting a result opens its report and actions.

Act on a result

  • Open Website opens the publisher or best known record using Website Links: a new built-in Browser tab by default, or the macOS default browser when selected.
  • Add to Library begins the placement workflow described below; after that, Show in Library returns to the managed paper.
  • Download retrieves the paper file. PDF opens an existing local PDF in Preview, and Delete PDF removes that managed download and resets its status.
  • When a reading note exists, Note opens it in the right-side drawer. The list compresses but keeps its own scroll position. Delete Note removes the note and resets analysis status.

Read an existing Note

Note appears when a reading note has already been generated. It opens the saved note on demand in a right-side drawer; the report area compresses and each side scrolls independently. Drag the divider to resize the note. Hide list gives the note more space; Show list restores the report. Closing the drawer keeps the note. Delete Note is a separate action that removes it and resets its analysis status. Links in the note follow Website Links.

Add a Journal result to Library

  1. Choose Add to Library on the result. The Library destination chooser opens without leaving the selected date.
  2. Choose the target Library folder. This is the visible folder placement for the managed paper.
  3. Complete the add. The card changes to Show in Library; use it to reveal the existing placement later.

The operation links the Journal discovery to the canonical paper, preserves its source and run provenance, and adds the chosen Library placement. It does not automatically download a PDF. Choose Download separately when you also want a local file. If the paper is already managed, Show in Library reveals it instead of creating a duplicate identity.

Per-paper status text and the bottom progress area make completed downloads and background work visible, which helps avoid repeating the same action.

About Gewu Insight

Visual Identity and Cultural Elements

Gewu Insight uses three related marks—the calligraphic Chinese name, the app icon, and a seal-script watermark—to connect a contemporary research workspace with the longer Chinese tradition of examining things in order to form insight.

The marks do not decorate every surface. Each has a different job: the icon identifies the application, the calligraphic name gives the product a human signature, and the quiet seal-script pattern belongs to transitional or otherwise empty space.

The calligraphic name

This is a 祝枝山行草集字 composition: four separately documented historical character forms were assembled into one wordmark. It is therefore accurate to call it “a collection of characters in the calligraphic style of Zhu Zhishan,” but not “a title written by Zhu Zhishan.” No surviving single inscription titled 格物洞見 is being claimed.

How the four characters were assembled

Reading orderReference characterRecorded hand and scriptRole in the product artwork
1格祝枝山 · 行书Begins the product name when read from the right.
2物祝枝山 · 草书Completes the classical term 格物.
3洞祝枝山 · 草书Introduces 洞見, insight gained by seeing through a subject.
4見祝枝山 · 草书Closes the traditional form of the name.

The selected glyphs were optically balanced into a common line: scale, spacing, ink tone, edge cleanup, and transparent alpha were normalized while the characteristic strokes were retained. The production preparation used a Codex-assisted image workflow. The interface and accessibility text use the contemporary simplified product name 格物洞见; the artwork deliberately preserves the traditional character 見 and traditional right-to-left composition.

Provenance and reuseThe character links above are retained as provenance for the design process. The source thumbnails do not state a clear open-reuse licence. They should not be treated as public-domain assets merely because they are viewable online. The assembled Gewu Insight product artwork is distributed under the repository's all-rights-reserved notice.

The app icon and the seal-script watermark

Why the three marks are used differently

Icon · recognitionUse at application scale: Dock, startup identity, About, and platform packaging.
Calligraphy · signatureUse where the Chinese name can be read deliberately, especially the About panel and identity materials.
Seal script · atmosphereUse at very low opacity in startup transitions or quiet lower-right space, never where it competes with paper details.

Together the three registers establish the product's visual identity: the icon is contemporary and operational; the calligraphy is personal and gestural; the seal-script watermark is historical in reference but restrained in use. Their common purpose is to make the name visible without turning the research workspace into a themed illustration.

Handle Publisher and Network Access

Publishers can rate-limit shared VPN addresses or automated-looking traffic. Gewu Insight reduces overlap and request rate, but it cannot remove a publisher block.

If a publisher page is blocked

  1. Stop repeated refreshes. Additional requests can extend a temporary block.
  2. Try your direct connection. If the page works with VPN off, the VPN exit IP is likely the blocked client.
  3. Use Open Website or an external browser. Complete any normal institutional login or publisher interaction yourself.
  4. Download only when authorized. Add a legitimately obtained PDF with Add File.

Why figures may arrive later

Figure and article-page retrieval is queued behind discovery work and uses caching. This reduces simultaneous RSS, page, and image requests to the same publisher. A paper can appear before its representative image.

Browser and your system network

The Browser tab uses native WebKit requests and does not proxy pages through the Python server. System proxy or TUN capture can send its traffic into Clash; only then do the active rules determine DIRECT or proxy routing. A DIRECT rule uses your current physical network, which must itself provide institutional access. Gewu Insight neither changes these rules nor guarantees a particular route; use Clash connection records to verify the actual route. See Browse, Bookmark, and Revisit Websites for downloads, sign-in limits, and the separate browser profile.

Service rate limits

Semantic Scholar, Google Scholar, and some publisher sources use shared pacing, cooldowns, or exponential backoff. Let the bottom status area settle before starting the same action again.

A startup-failure sheet is nonblocking; if the server recovers after that sheet appears, the stale sheet is dismissed automatically instead of continuing to interrupt a healthy workspace.

A brief reload during recovery does not mean the SQLite database was rebuilt or that another copy of Gewu Insight should be opened. If repeated recovery never reaches a healthy Library view, use the launcher log steps below.

Recovery reloads the workspace, so Browser's memory-only tabs and unsubmitted forms can be lost. Bookmarks and history already saved in SQLite remain. Save work on websites regularly; recovery is not a web-session or draft backup.

Automatic monitoring runs inside the local UI service, with startup delays, periodic checks, and saved completion/retry state. Keep the Mac awake and the service running. Closing a window does not necessarily stop that service. Quitting the App stops a server it started; a separately launched server must be stopped separately. A late launch checks work that is due rather than guaranteeing a run at an exact minute.

Troubleshoot Common Problems

Start with the visible status and the selected work. Avoid broad repair actions until you know whether the problem is network, metadata, database state, or a local path.

A PDF cannot be found after a move

  1. Reselect the paper and try Show in Finder.
  2. If the move happened in Gewu Insight, close and reopen the item to refresh the view.
  3. If the file was moved manually in Finder, return it if possible, then organize it through the app.
  4. Check Recycle before importing another copy.

Paper Files shows Missing File

This label is a path-state warning, not a failed metadata lookup: SQLite still knows the resource, but the recorded file path does not currently exist. Check Show in Finder, the corresponding data/Associated Files bundle, and Recycle. If the file was moved outside Gewu Insight, restore it before reorganizing it through the app. Do not delete the row merely because its filename resembles the default PDF; explicitly typed attachments and the default resource remain visible for recovery.

Quick Look is slow on the first open

A large or previously unseen PDF may need an initial structural read and thumbnail render. The main document should appear before the full thumbnail strip. Leave the preview open briefly instead of pressing Space repeatedly; later opens can reuse page information and cached thumbnails. If the viewer never produces a page, use Open in Preview to check whether the file itself is valid.

PDF switching flashes in built-in Quick Look

The built-in preview can flash as it loads another PDF. Open Setting > Quick Look Settings, choose macOS Quick Look for all files, and Save to use the system panel for rapid comparison. Up and Down still follow the selected files. This changes the preview method; it does not alter your PDF files or default-file choices.

The wrong file is the default

  1. Open Paper Files and verify every file type.
  2. Correct a mislabeled Corrected published version, Published version, Accepted manuscript, or Preprint; expand the size footer to set annotation separately.
  3. Choose Set as Default for the desired valid file, or choose Use Automatic Selection to resume automatic selection.

A duplicate appears after download

Compare file size and classification. New downloads use exact SHA-256 and PDF content fingerprints. A copy with annotations may be retained intentionally. Exact byte duplicates are reused, while clean and annotated peers can both remain. Keep the intended default before deleting any redundant non-default row.

A monitor shows no papers

Read the source status. An empty successful source is not the same as a failed fetch. In Subject Monitor, allow scheduled source-level retries to finish, or use the selected subject's refresh command when a manual retry is needed. In Journal Monitor, confirm the date and filters. If a VPN is involved, test a direct connection without repeatedly refreshing.

A journal count and the visible cards disagree

This is usually expected when Field Filter is active. Journal counts describe all stored papers for the selected journal and day; field choices narrow the visible cards. Clear or broaden the field selection before diagnosing a missing fetch.

A journal disappeared from the configured list

Open Journal Settings and inspect the disabled history before editing configuration files. Removing a journal disables its subscription but preserves previously collected papers and history. Add it again to restore monitoring. Because the subscription list is SQLite state, replacing source files should not be used as a journal-list repair.

LaTeX remains visible as source text

On a cold launch, allow the math renderer a moment to become ready. The active day should re-render automatically. If raw $...$ text remains, check network availability for the renderer, then reload the same view once; switching calendar dates should not be required.

Folder Loader looks incomplete

Open the live or previous Loader log and the result guide. Confirm the metadata mode, source path, and any stop action. Re-running the same source should reuse existing files rather than overwrite the primary PDF.

A default file cannot be deleted

The preferred Default and the protected physical primary file are not always the same resource. Set as Default changes the reading preference, not the Library's compatibility primary path; switching defaults does not guarantee that the old file becomes deletable. Remove ordinary non-primary resources through Paper Files. To remove the managed paper itself, use the normal Library reference/Recycle workflow, which preserves shared references. Do not bypass a primary-file warning in Finder. An Invalid file remains an audit record and is never eligible to become default.

Change where website links open

Open Setting > Website Links and save System Default Browser to use the browser selected in macOS. The default, Gewu Insight Browser, opens a new built-in webpage tab or reuses its unused first tab. This covers website actions in all five research views, including publisher arrows, DOI/arXiv links, scholarly profiles, citation-source links, and links inside Note. Existing web pages stay open. Local PDF, Preview, Finder, download, and file-import actions are unchanged.

Home works offline but a website will not load

Home displays local Favorites without a Google request. Missing site icons fall back to initials; they do not prevent opening Home. Search results and account actions require a connection. Read the load error, check the destination and Clash route, and try Reload once. A website may reject embedded browsers or have its own session policy; an unsupported-browser banner alone does not prove why a sign-in ended. Open in Safari is a manual compatibility fallback, with a separate sign-in session.

A publisher stays on security verification

A verification loop does not establish that you were identified as AI. Browser supports standard internal child documents used by embedded widgets, but a publisher's verification can still reject an embedded browser. Try Reload once; if the loop persists, use Open in Safari. Safari has a separate session. For publisher support, note the public URL, time, and displayed Ray ID, without sharing cookies or passwords. Do not repeatedly retry or bypass the challenge.

AutoFill does not appear or does not fill

Automatic triggering is deliberately limited to an explicit click in a clearly marked login field. Ordinary email, search, registration, verification-code, and uncertain fields do not qualify. Cancellation uses up the automatic offer for that field kind/site during the App session. Right-click the actual input and choose AutoFill > Passwords to retry manually.

Unlock and select the appropriate entry yourself. If the item says Passkey and shows a creation date, it is not a text password. If a real Password entry closes without filling, macOS or that website may not support the return path in this embedded view. Gewu does not read your vault, relay credentials, or submit forms to work around it. Use the website's supported login flow or Safari; do not send passwords or unmasked credential screenshots in a support report.

ImportantBefore any manual filesystem repair, quit the app and make a full backup of the database and managed files together.

Reference

Storage Reference

These paths describe the managed project layout. They are useful for backup and diagnosis, not for routine manual reorganization.

  • data/paper_monitor.sqliteAuthoritative database for papers, identities, relationships, settings, operational state, Browser bookmarks, and visit history. May contain saved metadata API keys; treat backups as private.
  • data/cache/journal_logosRebuildable local image cache for configured Journal Monitor logos.
  • data/LibraryVisible main Library root and compatibility primary files.
  • data/SpacesIndependent Space roots.
  • data/My PublicationsManaged local files for My Publications.
  • data/Associated FilesMirrored bundles for versions, supplements, and attachments.
  • data/pdfsLegacy managed PDF location retained for compatibility where needed.
  • reportsGenerated reading notes and reports. These are artifacts, not the database.
  • logs/paper_monitor_launcher.logmacOS launcher diagnostics when the local UI cannot start.

Quick Look page thumbnails use a separate, automatically trimmed temporary cache. It is rebuildable preview data, not part of the Library, Associated Files, or the SQLite record, so it does not belong in a research backup.

Browser website data and its disposable favicon cache are managed by macOS outside the project. They are separate from SQLite bookmarks/history and from the monitor caches listed above. See Browser and credential backup boundaries before moving to another Mac.

Associated Files layout

An associated bundle follows the managed scope and path, then a work-specific bundle. Its children separate Versions, Supplements, and Files. The exact physical name can change as the paper moves; the Gewu Key remains stable.

Database and exports

SQLite is the only source of truth. JSON, HTML, Markdown, Word, LaTeX, and PDF outputs are exports, diagnostics, or reading artifacts. Editing one of them does not edit the Library record.

ImportantDo not delete, rebuild, or “clean” the database because a generated JSON file looks stale. Diagnose the selected record and local path first.
