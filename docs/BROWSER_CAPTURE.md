# Browser article capture

Save to Gewu joins the built-in Browser to the existing paper, Library and Paper Files model. The toolbar opens a trusted workspace review panel. It does not change the ordinary Save Download action. Safari extension packaging and native messaging are future adapters, not part of this implementation.

## Flow and boundaries

1. An explicit toolbar command snapshots the current native tab, document generation, URL, Open Website context and bounded article metadata/PDF candidates. The one-shot collector runs in an isolated WebKit content world. It reads publication meta tags, scholarly JSON-LD and PDF links; it does not read inputs, credentials or the whole document body.
2. `capture_begin` creates a short-lived memory ticket and returns a review without writing papers/files/placements. Known DOI/arXiv aliases reuse canonical records. Identify can resolve an identifier through the existing bounded Crossref/arXiv clients. A title-only record requires explicit confirmation.
3. A PDF can be retrieved through the source WKWebView's session into a temporary native file, or chosen by the user. Native retrieval is bound to the snapshotted document and allowed candidate. Public-URL rules, MIME/size checks, a transfer timeout and backend readable-PDF validation apply. The native helper uploads bytes only to the workspace's loopback endpoint with a separate, one-purpose capability. Upload redirects are refused and no capability is sent to publishers. Remote pages receive no bridge or API access.
4. The destination reuses the Monitor Add to Library column picker: My Library/Spaces, successive folder columns and a full selected path. Confirm updates the capture destination only; Cancel preserves it, and Save to Library performs the import. Recycle and trashed folders are excluded. The reviewed server-side candidate is checked against PDF/page evidence and rechecked against canonical identity immediately before Save. Open Website context is a hint only. Save adds/reuses the paper and selected active Library or Space placement, records sanitized source provenance, and uses `attach_file_to_paper` plus the existing Library file reconciliation. SHA-256 duplicates reuse existing resources. The review suggests Published version only for recognized publisher main-PDF routes with a matching title-page DOI, or Preprint for native downloads bound to a standard arXiv PDF route (even if text identity extraction fails or finds a later publication DOI) and recognized bioRxiv/medRxiv, ChemRxiv and Research Square PDF routes with preprint identifiers. Journal metadata on the article record never changes a preprint copy into Published version. Supplement/peer-review/correction evidence takes precedence; uncertain and local files remain Unknown. Users can change the suggestion, and Identify preserves that choice. Classified article PDFs use the existing primary-file promotion and Main Files paths, so the Library icon and Space preview receive the same main PDF. File source is independent of File type and follows the bound PDF URL: recognized publishers use Publisher; arXiv, bioRxiv, medRxiv, ChemRxiv and Research Square use Preprint server; institutional repositories use Institutional repository; other remote hosts use Other. A selected local PDF uses User import without webpage provenance. Manual Default stays sticky. An explicit re-save repairs an old unclassified Browser resource in place, preserving its resource ID, Gewu Key, hashes and placements; known or manually overridden file types are not rewritten.
5. Tickets are DB-scoped, limited to 16 and expire after 20 minutes. Cancellation cleans staging; native cancellation also releases the retained snapshot. Repeated Save returns the same result. File failure after metadata commit is explicitly reported as partial success and remains retryable. No schema migration, JSON authority or automatic monitor classification is introduced.

## Adapter API

The trusted same-origin `/api/browser` actions are `capture_begin`, `capture_review`, `capture_save`, and `capture_cancel`. PDF bytes go to `/api/browser-capture-file` with `X-Gewu-Capture-Token`; browser-origin uploads must still pass the existing same-origin/Host checks. Native uploads include the requested PDF candidate in X-Gewu-PDF-Source; the backend requires membership in the snapshotted candidate list. Local uploads omit it and have no resource source URL or host detail, even when a publisher page is open. File Source and its host detail come from the actual bound PDF candidate, never from the page URL or the reviewed File type. The resource source URL stores only that candidate after authorization-URL filtering; paper-level browser observations separately retain the sanitized page URL. The entry channel remains `added_via="browser_capture"`. Exact duplicate reuse preserves the existing resource’s source, URL and any user edits; it does not retroactively relabel earlier imports. This endpoint does not accept arbitrary local paths or fetch a URL. A future Safari adapter must use an authenticated native handoff; it must not relax these origin/host requirements.

Recognized signed/authorization URLs are excluded from persisted source fields. Metadata services receive the requested scholarly identifier only. Temporary files are not research-library records or exports. A successfully saved ordinary source URL is retained as provenance; opening a page by itself does not import it.

Save responses include the committed Paper Files snapshot and article metadata, including duplicate reuse and retryable partial saves. The workspace installs that snapshot immediately; earlier in-flight file reads cannot overwrite it. The success message offers Show in Library, using the returned paper/item IDs to select the exact saved placement in its Library or Space folder. Saving keeps Browser open until that explicit navigation action.

## Validation

`tests/test_browser_capture.py` covers SQLite/file behavior and real local API upload/permission checks using temporary roots, plus the inert native lifecycle probe in `tests/browser_capture_native_probe.m`. `tests/browser_capture_ui_probe.cjs` exercises the real collector and review UI with generated DOM and in-memory API responses: no user profile or real website traffic. The native probe checks staging cleanup, redirect rejection, native URL authority, document changes, candidate binding and late cancellation callbacks. These tests do not establish universal publisher or institutional-download compatibility.

Preprint route references: [bioRxiv documentation](https://www.biorxiv.org/about-biorxiv), [bioRxiv/medRxiv API](https://api.biorxiv.org/), and [Research Square preprint indexing](https://support.researchsquare.com/support/solutions/articles/6000271865-where-are-preprints-posted-on-research-square-indexed-). Recognition is bounded; other hosts or insufficient evidence remain Unknown for review.
