# Publication updates

**Refresh Info** checks the saved original DOI for subsequent corrections, errata, retractions, expressions of concern, withdrawals and addenda. This lookup runs when metadata is refreshed, including a manual single-paper refresh or a folder/all-Library metadata job. Saved Library, Space and My Publications papers do not have an automatic periodic metadata-refresh schedule. Journal Monitor can also discover notices in its own fetched results. Neither route is a continuous retraction watch or an instant publisher notification service.

The lookup uses Crossref's documented [`updates` DOI filter](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/). An explicit outgoing relation in the returned notice must match the original DOI. A title match, citation, related-paper link or retracted-original flag alone does not authorize a merge. Availability depends on publishers and other Crossref data sources depositing the relationship; an empty successful check is not a guarantee that no notice exists anywhere.

Verified events appear in the original article's **Paper Files**, with their type, date and official DOI link. They have no independent paper identity or Gewu Key. Existing article PDFs, analyses, bibliographic identity and manual Default are retained. Repeating Refresh Info reuses the event. These event entries do not imply that a notice PDF was downloaded.

Journal Monitor shows retained events in a collapsed **Publication updates** section below **Monitor Summary** in the left sidebar. It uses the sidebar text size and expands within the sidebar without moving journal tabs or shrinking the article list. The event count and list follow the current Journal and Field selections, including Other Fields and All Fields. Linked events use the original article’s classification; unresolved events use their retained notice metadata through the same classifier as paper cards, without fetching or creating an original for filtering. Events remain separate from research-paper counts. **Add to Library** resolves the notice to the original article. If the original already exists, its Gewu Key is reused. If absent, the desktop lookup may create the verified original as a metadata-only record in the selected default destination. The notice never becomes a standalone paper. Legacy notice cards reaching the shared Add handler are routed through the same resolver.

Missing, self-referential, multiple or conflicting original relations remain reviewable; the system does not guess the target. Failed update queries are reported as unavailable or rate-limited in the Refresh Info result, and already saved notices are retained. This feature does not change MCP import permissions, enable network resolution in MCP imports, sweep old records or move old notice files automatically.
