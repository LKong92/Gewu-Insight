# Independent Monitor downloads

Journal Monitor and Subject Monitor share the paper-card download and Add to Library handlers. Background completion updates only the affected paper's controls and cached record. It must not render a whole workspace, restore an old scroll snapshot, select a paper, close Quick Look, or return from Browser.

In-flight download and Library-add state is held per paper, independently of DOM nodes. Recreated cards recover that state; retained Monitor surfaces receive the same updates. Failures remain visible on the affected card. The next Library file read refreshes any file list cached before the download finished.

All UI callers share one pending download promise per paper, including its publisher fallback and supplementary-file sequence. A second click while that request is active joins it. An ordinary Download reuses a valid local PDF even if a legacy overlapping request left a failed status; a missing PDF is fetched again. A later explicit refresh remains available after completion. Identical refreshed bytes reuse the same file/resource; changed bytes retain the preceding version. The UI server serializes a paper's download, resource registration, path reconciliation and Library additions with a process-local reentrant lock. Different papers remain concurrent. This is not a persistent download queue and does not resume downloads after quitting the App.

Each download has its own temporary directory inside its destination filesystem. Main PDFs, supplements and merge intermediates no longer share fixed names in a Library folder. Complete new output is published exclusively so another download cannot overwrite it after a filename collision. Renaming updates both the paper path and the corresponding Paper Files path in one transaction. A database failure rolls back the rename and its path updates; custom resource labels and original import-source paths remain intact. Existing explicit refresh/version and Default-selection rules remain in force. This change does not remove pre-existing unregistered duplicate files.

All supported native publisher fallbacks now use the same external website store and WebKit identity as Gewu Browser, with separate script controllers. APS and ACS establish the article page before following the PDF target, as Science and Nature do. WebKit chooses its normal navigation headers. This does not override the user's system or Clash routing. APS Harvest remains the first direct APS candidate; its hostname has its own network routing and access checks, independent of `journals.aps.org`.

Automatic supplementary discovery downloads PDFs only. Movie, audio, archive, spreadsheet and Word attachment links are skipped, including misleading PDF labels on non-PDF filenames. Same-page section anchors are not treated as downloadable attachments. Empty supplementary discovery retains a successfully obtained main article; supplementary discovery/download failures appear as warnings without turning a saved main PDF into a failed download. Existing manual Word-file handling remains available. A Nature secondary-file redirect is also rejected in the direct downloader, so it cannot stand in for the main article.

## Nature background fallback

For Nature-family DOIs (`10.1038/`), a failed direct download now opens the article in an off-screen WebKit page using Gewu Browser's existing website session. It requests the published PDF first; an explicitly linked `_reference.pdf` remains an Accepted manuscript. Verification or access failures give Browser guidance instead of silently substituting an attachment or another article.

Supplement discovery accepts Nature's official Springer Nature file hosts and excludes peer-review, reporting-summary and source-data links from the scientific supplement merge. The follow-up targets the newly downloaded resource, preserves a manually selected Default and avoids appending identical supplementary bytes twice. When the direct main download succeeds but supplementary discovery fails, its resource ID is carried into the background follow-up. Articles without supplementary files retain the successful main-download response.

## Science main PDFs and supplements

Science downloads retain the main-article-then-supplement merge workflow. Direct discovery and the native browser reject `/suppl/`, `_sm.pdf`, MDAR/checklist links and clear supplementary cover headings as main articles. The browser first loads the article page with its existing publisher session, then requests the official main PDF. Browser verification and article-access restrictions remain effective; missing main articles produce an explicit failure, with the response status/path retained for diagnosis.

Native publisher downloads pass the actual PDF response URL and publisher filename to Paper Files. Temporary Gewu names are never used as durable filenames; missing publisher names fall back to the existing metadata naming template. When the downloaded file is Default, active placements for that paper that still contain an exact old native staging UUID name are renamed through the existing file/alias synchronization. This prevents a later supplement merge from restoring the obsolete name. Custom placement names and a manually preferred other version are preserved. This shared filename/provenance fix also applies to the other publishers using the same native downloader.

Science merges record exact original component hashes in the generated PDF, so repeated supplementary bytes are appended once even across retries. The merge targets the downloaded Published version when the user has another manual Default. Staging, validation and a recoverable copy protect the previous PDF if writing or database registration fails; resource size, page count and fingerprints update with the result. Shared or linked originals are copied. Existing legacy files are not scanned or repaired in bulk.

## Regression coverage

- `tests/test_monitor_paper_updates.py`: generic Subject responses retain group/selection context; background downloads survive navigation; repeated calls coalesce, different papers proceed independently, and failures permit retry.
- `tests/monitor_download_ui_probe.cjs`: real product card handlers and CSS on synthetic DOM in Chrome; both Monitor modes retain status, node identity, scroll, input focus and preview state while adding another paper. List recreation and cached-background failures preserve operation status; Browser and Library remain selected on completion.
- `tests/test_download_concurrency.py`: real temporary UI HTTP service and generated PDFs. Adding another paper completes while a download waits; repeated requests produce one registered PDF; simultaneous papers retain distinct bytes; colliding output names never overwrite each other. Sequential clicks, repeated identical refreshes, stale download status, missing local files, resource-only rename and rename-failure rollback are also covered.
- `tests/test_science_download_integrity.py`: generated main/supplement PDFs, bad redirects and covers, exact duplicate retries, filename/source provenance, manual Default preservation, shared originals and database-failure rollback.
- `tests/science_download_webkit_probe.m` and `tests/science_download_ui_probe.cjs`: product native delegates with an ephemeral WebKit DOM and intercepted navigation; real frontend orchestration with deterministic native responses. Neither probe uses real papers or publisher requests.

All automated reproduction uses temporary SQLite and synthetic PDFs. Cleaning up existing real duplicates is separate maintenance: require explicit scope authorization, verify byte hashes and other references, back up the affected records and retained files, preserve identities/classification/Default, and use recoverable macOS Trash with verified destinations and rollback. Ordinary downloads never perform a Library-wide cleanup.

An APS PDF endpoint may return an **Authorization Required** HTML page even when its abstract opens normally. Background downloads recognize that explicit page and ask for institutional or personal subscription access. Other timeouts retain the last response detail and direct the user to check access in Gewu Browser; they do not establish that a subscription is available.
