# Paper-level metadata refresh

Paper Details in Library, Spaces, My Publications and Author Monitor has one **Refresh Info** action. DOI and arXiv remain separate editable rows; Return saves an identifier without a remote lookup. The refresh action saves a pending DOI edit, then resolves the paper's saved identifiers. An arXiv-only record does not require a DOI input. The existing Library metadata-refresh Loader command uses the same implementation, with shared Quick and Full modes.

`metadata_refresh.py` checks arXiv metadata, exact DOI records from Crossref/OpenAlex, exact Semantic Scholar external IDs, configured ADS and DOI-based PubMed enrichment. Explicit arXiv publication DOI, an exact external-ID association, an OpenAlex hosting location or Crossref `has-preprint` relation can fill a missing counterpart. A title search needs an explicit matching arXiv location; reference lists, abstracts and conflict/history messages cannot supply the paper's identity. Service records whose identifiers disagree are ignored. A newly linked DOI loads publication metadata in the chosen mode while preserving the preprint record.

Existing published identifiers and manual corrections/clears are retained. A DOI already assigned to another canonical paper is reported without merging. A verified preprint DOI transition can change the title and venue, but disjoint authors plus a contradictory title remain a conflict. An explicit DOI correction retires remote URLs for the replaced DOI into raw history, leaving physical file paths intact. Refresh changes bibliographic fields and provenance only: no Key replacement, Library placement, file download, resource update, classification change, Default change or deletion.

Network work precedes writes. Repeated requests for the same database and canonical paper share an in-flight result; a detailed request following a lightweight check still obtains detailed metadata. Identifier edits during lookup reject the stale result. Current unrelated raw metadata is retained when the result is applied. Each result persists its last check, sources, changed fields, conflicts and next eligibility in the paper's SQLite raw metadata. Partial failures retain usable source results and are visible; Loader does not label them a completed refresh.

The shared Details toolbar uses two rows: Open in Preview / Download / Open Website, then Google Scholar / Get DOI / Refresh Info (when available). Get DOI retains its existing DOI and arXiv extraction behavior. Refresh results, last-check time, source outcomes and conflicts appear only in a temporary tooltip below Refresh Info, never as a persistent panel block. Hover or keyboard focus reveals it; pointer departure, focus departure, Escape, scrolling or a Details rerender dismisses it. Detailed busy and error feedback use this same surface. The unified workspace footer also shows running refreshes and brief completion, partial-result or error notices. Concurrent Library/Space refreshes are counted separately from other downloads/imports; finishing a refresh retains an ongoing download indicator. My Publications uses its existing activity slots, and Author Monitor uses the secondary paper-information status. Completion updates the originating workspace even after the user switches away, without navigating or moving focus. Unsaved editors receive the new tooltip report without rebuilding their DOM.

## Explicit identifier corrections

DOI and arXiv editors share the same save behavior in Library, My Publications and Author Monitor. Enter waits for the server to acknowledge the identifier, leaves editing on success and shows green **Identifier updated** (or **Identifier saved** for an unchanged value) above the bibliographic fields. Invalid input remains editable with an error. Delayed saves do not move focus or place notices on another paper. Refresh Info also saves a changed DOI before requesting metadata.

Replacing an existing identifier records a pending correction; clearing it and then entering a replacement preserves this intent. Adding an identifier to an empty row retains normal enrichment behavior. A pending correction uses the newly saved identifier as its metadata anchor. A usable primary response must return that exact DOI/arXiv ID before the old automatic bibliography is replaced. Old bibliographic fields, source identifiers, citation counts and Semantic Scholar data are archived in the paper's correction history rather than mixed with the new work. Missing or mismatched primary responses retain the previous information and pending correction for retry. Provider cooldowns still apply.

Corrections update the same canonical object transactionally and never merge another Gewu Key. Another owner of the entered identifier or a newly discovered identifier remains a conflict. Key, files, resource IDs/classification, manual Default, directory references and user notes remain intact. Explicit identifiers in the other row are retained; unverified old automatic relationships must be rediscovered. Once a correction is applied, subsequent refreshes use the ordinary identity guards again. The preceding version's saved DOI edits are recognized only when old source DOI or edit history demonstrates the replacement; an old manual flag alone does not waive conflict checks. No startup migration or historical sweep is performed.

## Shared entry points, history and scheduling

`metadata_refresh.py` owns per-paper metadata work. Details uses Full; Loader import and Library/Space folder or all-Library tasks choose Quick/Full. Quick updates core bibliographic fields and verified DOI/arXiv relationships; Full also requests detailed Semantic Scholar, configured ADS and PubMed enrichment. Automatic mode remains separately lightweight. Missing-identifier recovery remains an import step, then invokes the selected mode once rather than forcing Full for recovered papers. Finder drops retain Skip metadata.

All entry points record outcomes in `paper_metadata_refreshes`. Batch and import jobs skip successful compatible checks within three days; Full satisfies Quick, not the reverse. New history records the checked identifiers, so a changed DOI/arXiv does not inherit an unrelated cooldown. Legacy batch checks can be reused when their recorded primary identifier still matches. Explicit Details requests bypass this duplicate-check cooldown. Source results are cached per paper and identifier pair in SQLite raw metadata, with separate Semantic Scholar field-set modes; partial batch retries reuse recent found/not-found responses and retry failed sources. Changed counts compare bibliographic projections, not timestamps or cache writes.

`metadata_network.py` is active only within metadata work. Request spacing and persisted provider Retry-After pauses are shared by these entries; HTTP 429 or Retry-After 503 stops that source rather than immediately retrying. With no Retry-After, the local fallback is five minutes, not a claimed remote quota. Existing provider safeguards still apply. No Scholar request is introduced and its protection remains independent. Ordinary HTTP/download calls do not enter this policy.

`metadata_jobs.py` keeps candidate snapshots and mutable checkpoints separately in SQLite settings. Folder scope recursively includes active descendants, excludes Recycle/deleted trees, and deduplicates canonical paper IDs (Gewu Keys). Each item is rechecked against current scope before processing. No-ID and removed items are explicit outcomes. Pausing finishes the current paper; Continue resumes the saved cursor. After process restart, interrupted jobs are paused until continued. Recent tasks are available in the Loader; each log retains the latest 200 lines while totals/candidates persist. Overlapping requests share one in-flight paper; a higher-detail request receives the missing detail. Per-database work is serialized at paper boundaries with single-paper priority above import, batch and automatic checks. The automatic daily quota is not applied to user-started batches.

Folder context menus expose **Refresh Info** only for active folders. The existing task window shows the full recursive scope, Quick/Full, progress, separate outcome counters and Pause/Continue. The Library footer observes jobs independently of downloads/imports. Completion updates visible metadata without selecting another paper, rebuilding a draft or switching workspaces. No source file, placement, Key, resource classification or Default is modified by refresh.

## Automatic checks and interaction

Library, Space and My Publications placements select saved canonical papers once, excluding the system Recycle tree. The queue alternates saved-paper publication checks with existing Author Monitor completion work. Both share one worker, 20 papers per batch, 80 per local day, approximately 120-second slices checked between papers and at least 300-second rests. Reservations survive restart. Initial candidates favor newer publications; previously checked papers become eligible after seven days, backing off to thirty days after three unchanged checks. Source failures retry no sooner than one day. Eligibility is not a guarantee of a check on that date: the shared queue and daily allowance can delay it. No Google Scholar request is added.

Explicit refresh uses the same per-paper coalescing but is outside the automatic daily allowance. Repeated clicks on the busy Refresh Info button are ignored; other actions remain available. Results update the original paper's cached metadata without switching workspace, paper selection or keyboard focus. An open editor or unsaved draft keeps its DOM. A 30-second local poll observes completed results for visible Details; this poll does not trigger remote refreshes. Older results cannot overwrite a newer check. File snapshots retain their resources while receiving updated paper metadata.
